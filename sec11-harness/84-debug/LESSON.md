촬영: VS Code 내장 터미널(code-server), Claude Code v2.1.296, 오토 모드, Opus 5.5, 2026-10-17. 녹화 컴퓨터 시간대 미국 동부(EDT). 앱 브랜치 `sec11-spec`(80강에서 이어짐).

## 버그
`subway.html` 지도 아래 「실시간 열차 … 기준」, 「실시간 도시데이터 … 받음」의 시각이 `toLocaleTimeString("ko-KR", {...})`로 만들어지는데 `timeZone`이 없어서 **보는 컴퓨터의 시간대**를 따름. 미국 동부 컴퓨터에서 「오전 03:32 받음」인데 같은 화면의 시간 슬라이더(서울 시각)는 16:32. 같은 파일의 붐빔 그래프(`kstClock`)는 `timeZone: "Asia/Seoul"`이 있어 맞음.

```text
고치기 전에 재현 스크립트부터 만들어 줘. TZ 환경 변수로 다른 나라 시간대에서 돌려서, 지금 코드가 틀리는 걸 먼저 보여 줘
이제 고치고, 같은 스크립트로 다시 확인해 줘
방금 버그 잡은 순서를 CLAUDE.md에 디버깅 규칙으로 짧게 남기고 커밋해 줘
/exit
git log --oneline -4
```

## 화면에서 본 것 (녹화 1회, 2026-10-17 04:05~04:09 EDT)
- 원인(25초): `subway.html` 1424·1517줄, `ko-KR`은 표기만 정하고 시간대는 컴퓨터 것을 따름. 서버의 `updatedAt`(UTC ISO)은 문제없음.
- 재현 스크립트 `scripts/repro-received-time.mjs`(49초): `subway.html`에서 시각 식을 **그대로 뽑아** 고정 시각(서울 09:04:05)을 넣고, `TZ`를 바꿔 자식 프로세스로 5개 시간대에서 실행. 결과 서울만 맞음, UTC·뉴욕·런던·콜카타 틀림(뉴욕은 전날 20:04) → 「5개 시간대 중 4곳에서 서울 시각과 다름 (종료 코드 1)」.
- 고침(21초): 두 곳에 `timeZone: "Asia/Seoul"`, `hour12: false` → 같은 스크립트 5곳 모두 맞음(종료 코드 0), `npm test` 143개 중 139개 통과·실패 0.
- CLAUDE.md 규칙 2줄(시각 표기, 버그 잡는 순서) + 커밋 `382d12b`.
- 브라우저(같은 EDT 컴퓨터): 고치기 전 「오전 03:32:19 기준 / 03:32 받음」 vs 슬라이더 16:32 → 고친 뒤 「17:09:23 기준 / 17:09 받음」 vs 슬라이더 17:09.
