# /web-page — 체크리스트로 웹 페이지 만들기

사용자가 준 요구사항:

$ARGUMENTS

(위가 비어 있으면 대화에서 사용자가 말한 요구사항을 쓴다.)

## 1. 요구사항 체크리스트 정리

위 요구사항을 아래 네 항목으로 나눠 `-` 목록으로 정리한다.

- **이름**: 페이지(가게·서비스) 이름, 제목
- **내용**: 보여 줄 정보 (메뉴·가격·소개 글 등)
- **동작**: 누르면 무엇이 일어나는지, 계산·저장해야 할 것
- **모바일**: 휴대폰 화면에서 어떻게 보여야 하는지

비어 있는 항목이 있으면:
- 요구사항이 아예 없으면 네 항목을 채워 달라고 묻고 멈춘다.
- 일부만 비었으면 합리적인 기본값으로 채우고, 무엇을 가정했는지 체크리스트에 `(가정)`으로 표시한다.

정리한 체크리스트를 짧게 보여 준 뒤 바로 만들기로 넘어간다.

## 2. index.html 만들기

- 따로 말이 없으면 **`index.html` 한 파일**(CSS·JS를 안에 포함)로 만든다. 이미 있으면 먼저 읽고 요구사항대로 고친다.
- 모바일 대응은 기본이다. 375px 너비에서도 깨지지 않게 하고 `<meta name="viewport">`를 넣는다.
- 사용자가 입력하거나 고른 데이터(주문 목록, 할 일 등)는 `localStorage`에 저장해 새로고침해도 남게 한다.
- 아이콘만 있는 버튼에는 `aria-label`을 단다.
- 가격·숫자는 천 단위 쉼표로 표시한다.
- 외부 라이브러리가 필요하면 context7로 최신 문서를 먼저 확인한다.

## 3. screen-checker로 확인

만든 뒤 `screen-checker` 서브에이전트에게 다음을 맡긴다.

- `index.html`을 데스크톱 너비와 375px 너비로 열어 스크린샷을 찍는다.
- 체크리스트의 **동작** 항목을 실제로 눌러 보고 결과 화면도 찍는다.
- 문제점만 요약해 돌려 달라고 한다.

`screen-checker` 에이전트가 없으면 Playwright MCP로 직접 같은 확인을 한다.

문제가 나오면 고치고 한 번 더 확인한다.

## 4. 보고

- 확인에서 발견하고 고친 문제, 남은 문제
