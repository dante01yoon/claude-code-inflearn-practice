# /seoul-data — 서울 열린데이터광장 데이터 받기

사용자 요청:

$ARGUMENTS

(비어 있으면 대화에서 사용자가 말한 데이터를 쓴다.)

## 1. 서비스명 정하기

API는 `http://openapi.seoul.go.kr:8088/{인증키}/json/{서비스명}/{시작}/{끝}/{추가 인자…}` 모양이다.

- 사용자가 서비스명(영문, 예: `CardSubwayTime`)을 주면 그대로 쓴다. 대소문자까지 정확해야 한다.
- 데이터 설명만 주면(예: "지하철 시간대별 승하차") [reference/services.md](reference/services.md)에서 서비스명과 **요청인자 순서**를 고른다. 거기 없으면 WebSearch로 `data.seoul.go.kr <데이터 이름> OpenAPI 서비스명`을 찾거나, 데이터셋 페이지 주소를 받아 'Open API' 탭에서 확인하고 services.md에 더한다.
- 요청인자는 순서대로 붙고, 안 쓰는 칸은 공백(`%20`)으로 채운다. 예: `CardSubwayTime`은 `/월/호선/역`이라 역만 고르면 `/202508/%20/강남`.
- 필수 인자(날짜 등)를 모르면 샘플 키로 한 번 불러 보고, `ERROR-300`이 나오면 요청인자를 찾아 넣는다.

## 2. 받기

```bash
python3 .claude/skills/seoul-data/scripts/fetch.py <서비스명> [추가 인자…] [--line 호선] [--station 역] [--max N] [--format csv|json|both] [--out 경로] [--force]
```

- 지하철 서비스(`CardSubwayTime`, `CardSubwayStatsNew`)는 월·날짜만 위치 인자로 주고, 호선·역은 `--line`, `--station`으로 준다. 스크립트가 `/월/호선/역` 순서와 빈 칸(`%20`)을 맞춘다. `--line 2`는 `2호선`이 된다.
- 기본 저장 위치는 `data/seoul/<서비스명>_<인자>.csv` 와 `.json` 이다. 사용자가 위치를 말하면 `--out`으로 바꾼다.
- 한 번에 1,000건씩 끝까지 이어 받는다. 몇만 건 이상이면 먼저 `--max 1000`으로 받아 모양을 보여 주고 전부 받을지 묻는다.
- 같은 파일이 있으면 멈춘다. **원본 데이터이므로 덮어쓰기(`--force`)는 사용자가 원할 때만** 쓴다.
- CSV는 `utf-8-sig`로 저장해 엑셀에서 한글이 깨지지 않는다.

## 3. 인증키

스크립트는 `--key` → 환경변수 `SEOUL_API_KEY` → 현재 폴더 `.env`의 `SEOUL_API_KEY` 순서로 찾고, 없으면 `sample` 키(최대 5건)를 쓴다.

- **인증키를 직접 읽거나 화면·파일·커밋에 쓰지 않는다.** `.env`를 열어 보지 말고 스크립트에 맡긴다.
- sample 키로 받았으면 사용자에게 알린다: data.seoul.go.kr 로그인 → 마이페이지 → '인증키 신청'으로 일반 인증키를 받고, 프로젝트 `.env`에 `SEOUL_API_KEY=발급받은키` 한 줄을 넣으면 전부 받을 수 있다. `.env`가 `.gitignore`에 있는지도 확인해 준다.

## 4. 보고

한국어로 짧게 알려 준다.

- 받은 건수 / 전체 건수, 저장한 파일 경로
- 주요 컬럼과 뜻(이름으로 짐작되는 것만, 예: `HR_8_GET_ON_NOPE` = 8시대 승차 인원)
- sample 키였으면 5건뿐이라는 점과 인증키 설정 방법

## 5. 스스로 확인하기

받은 뒤, 보고하기 전에 스크립트 끝의 `[확인]`/`[불일치]` 줄을 보고 아래를 하나씩 확인한다.

- [ ] `RESULT.CODE`가 `INFO-000`인가 — 아니면 스크립트가 저장 없이 오류 코드와 힌트를 내고 멈춘다.
- [ ] 받은 건수가 `list_total_count`와 같은가 — `--max`나 sample 키로 일부러 줄인 경우만 예외다.
- [ ] (`--station`을 썼으면) 요청한 역만 들어 있는가 — 역 컬럼(`STTN` 또는 `SUB_STA_NM`)에 다른 역이 없어야 한다.

하나라도 틀리면 원인을 고쳐서 다시 받는다.

- 코드 오류 → 힌트대로 서비스명·인자를 고친다(`INFO-200`이면 달을 앞당기거나 역 이름 표기를 services.md대로 확인).
- 건수가 모자람 → `--max` 없이, 또는 끊긴 경우 그대로 다시 받는다.
- 다른 역이 섞임 → 인자 순서·빈 칸(`%20`)을 services.md와 맞춰 본다.
- 이번 작업에서 방금 만든 잘못된 파일은 `--force`로 다시 받아도 된다. 원래 있던 파일은 덮어쓰지 않는다.
- 두 번 고쳐도 안 맞으면 멈추고, 무엇이 안 맞는지 그대로 사용자에게 알린다.
