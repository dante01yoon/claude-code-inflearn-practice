# 섹션 4 · 31강 PRD와 ROADMAP.md를 클로드와 함께 쓰기 — "내 역은 몇 시가 가장 한가할까"

코드를 쓰기 전에 무엇을·왜·언제 끝인지 적는 **PRD(주문서)** 와 단계·확인 방법을 적는 **ROADMAP(이정표)** 를 클로드와 함께 씁니다.

## 개념
- PRD 다섯 칸: 누가 쓰나 · 무엇이 불편한가 · 꼭 필요한 기능 · 하지 않을 것 · 완료 기준
- ROADMAP = 단계 + 단계마다 확인 방법. 계획 모드가 작업 하나의 설계도라면 ROADMAP은 여러 수업에 걸친 설계도
- 계속 고치고 커밋할 문서는 저장소 파일로

## 입력한 것 (그대로)
짧은 프롬프트 1:
```text
서울 라이브 3D 지하철 레이어 PRD 써 줘. 핵심은 '내 역은 몇 시에 가장 한가할까'야
```
→ 클로드가 PRD를 **claude.ai 문서(Artifact)** 로 올림(저장소 파일 아님). 그 과정에서 9월 CSV로 질문을 검사:
지금 규칙(하루 전체에서 가장 적은 시간대)으로는 621행 중 414행이 04시대, 153행이 01시대가 답 → **사용자가 고른 시간 창(출근 06–09 · 낮 10–15 · 퇴근 16–19 · 저녁 20–23 · 직접) 안에서 가장 한가한 때 + 피크 대비 %** 로 질문을 바꿈. 예: 가산디지털단지 낮 → 11시대 2,040명, 08시대의 15%.

짧은 프롬프트 2:
```text
PRD 보고 ROADMAP.md 만들어 줘. 단계마다 다 됐는지 확인하는 방법도 적어 줘
```
→ `ROADMAP.md`(0단계 원본 정리 ~ 5단계 마무리, 단계마다 확인 항목). 기대값을 다시 계산하다 PRD 오류 2곳(783→784, 계양 낮 창 기록 없음)을 스스로 고침.

"프롬프트를 좀 더 자세히 써야 제대로 되니, 제대로 작성해 보겠습니다" — 자세한 프롬프트 (`claude --continue`로 이어서, 줄바꿈은 Shift+Enter):
```text
PRD는 클로드 문서 말고 저장소 docs/PRD.md 파일로 저장해 줘. 앞으로 계속 고치면서 커밋할 문서라 저장소에 있어야 해.
아까 물어본 세 가지는 이렇게 정할게: 카드는 새 방식(시간 창)으로 바꾸고, 3D에는 승하차 데이터가 있는 역을 모두 세우고, 기본 데이터는 9월 CSV로 바꿔.
ROADMAP.md의 PRD 링크도 docs/PRD.md로 바꿔 줘.
```
→ `docs/PRD.md` 생성, 결정 사항 장 추가, ROADMAP 반영. 새로 드러난 문제: 데이터가 있는 역이 남북 약 147km에 걸쳐 지금 3D 장면에 안 들어감, 노선 순서를 따로 정해야 함(34·35강).
