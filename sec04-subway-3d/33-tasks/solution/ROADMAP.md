# 로드맵: 내 역은 몇 시에 가장 한가할까

지하철 레이어 PRD([docs/PRD.md](docs/PRD.md))를 단계로 나눈 것이다. 단계는 순서대로 진행하고, 각 단계의 "확인" 항목이 모두 통과해야 끝난 것으로 본다.

공통 확인(모든 단계에서):
- `npm test`가 통과한다.
- `npm run check`가 `문제 0건`으로 끝난다.
- `data/` 아래 원본 파일이 바뀌지 않았다: `git diff --stat -- data/`에 아무것도 나오지 않는다.

## 핵심 정의

단계마다 같은 규칙을 쓴다. 자세한 근거는 PRD 4장.

- 값: 시간대별 승차+하차(`total`)를 그 달 일수(`usageMonth().days`)로 나눈 하루 평균.
- 후보: 사용자가 고른 시간 창 안의 시간대 중 값이 0보다 큰 것.
- 답: 후보 중 값이 가장 작은 시간대. 동률이면 모두.
- 피크 대비: 답의 값 ÷ 그 역의 하루 전체 최댓값.
- 시간 창 프리셋: 출근 06–09시대, 낮 10–15시대(기본), 퇴근 16–19시대, 저녁 20–23시대, 직접 고르기.

## 정해진 것 (PRD 9장)

- 역 요약 카드의 "가장 한가한 때"는 시간 창 방식으로 바꾼다. 하루 전체 최저는 남기지 않는다.
- 3D에는 승하차 데이터가 있는 역을 모두 세운다.
- 앱 기본 데이터는 9월 CSV로 바꾼다. 7월 JSON 파일은 원본이라 그대로 둔다.

## 1단계. 시간 창 안의 가장 한가한 때 계산

`stats.mjs`에 `quietestInWindow(row, hours)`를 추가한다. `hours`는 `HOURS` 순서의 시간대 배열이다(자정을 넘는 창은 `[22, 23, 0, 1]`). 기존 7월 JSON 5행으로 먼저 검증한다.

할 일
- [x] `quietestInWindow(row, hours)`: 위 정의대로 답 시간대 배열을 돌려준다. 창 안이 전부 0이면 `[]`.
- [x] `peakRatio(row, h)`: 그 시간대 값 ÷ 하루 전체 최댓값.
- [x] 시간 창 프리셋을 `stats.mjs`에 상수로 둔다(`index.html`과 테스트가 함께 쓰게).
- [x] `quietestHours`를 지우거나 `quietestInWindow(row, HOURS)`로 바꾼다. 3단계에서 카드가 새 함수를 쓰게 되면 화면에서 쓰는 곳이 없어진다. 관련 테스트도 새 함수 기준으로 옮긴다.

확인
- `tests/stats.test.mjs`에 아래 경우가 테스트로 있고 통과한다.
  - 창 안에서 0명인 시간대는 후보에서 빠진다.
  - 동률이면 모두 돌려준다.
  - 자정을 넘는 창(`[22, 23, 0, 1]`)이 동작한다.
  - 창 안이 전부 0이면 `[]`를 돌려준다.
  - 서울역(7월 JSON)의 낮 창 답이 정해진 값이다. 기대값은 데이터에서 직접 계산해 적는다.
- `node --test --test-name-pattern="창" tests/stats.test.mjs`로 새 테스트만 따로 돌려도 통과한다.

## 2단계. 9월 전 역 데이터 읽기

CSV를 읽어 API JSON 행과 같은 모양(`STTN`, `SBWY_ROUT_LN_NM`, `USE_MM`, `HR_<시>_GET_<ON|OFF>_NOPE`)으로 바꾸는 어댑터를 만든다. 변환은 읽을 때 코드에서 하고 원본은 그대로 둔다.

할 일
- [ ] CSV 어댑터 모듈(예: `subway-csv.mjs`). 브라우저(`TextDecoder("euc-kr")`)와 Node 테스트에서 함께 쓸 수 있게 디코딩과 파싱을 나눈다.
  - 열 이름 변환: `04시-05시 승차인원` → `HR_4_GET_ON_NOPE`. 23시 열은 `23시-24시`로 끝난다.
  - 값은 숫자로 바꾼다. `사용월` → `USE_MM`.
- [ ] 환승역 합산: 같은 역명의 행(78곳)을 합친 행을 만들 수 있게 한다. 노선별 행도 그대로 남긴다.
- [ ] 역 좌표: 역사마스터 CSV에서 읽는다. 이름이 다른 11곳(`낙성대(강감찬)`, `상봉`, `평택지제` 등)은 매핑표로 처리한다.
- [ ] `scripts/check-data.mjs`가 9월 CSV도 점검할 수 있게 한다(확장자로 구분). 인자 없이 실행하면 9월 CSV를 점검하게 기본 경로를 바꾼다.
- [ ] `index.html`이 9월 CSV를 기본 데이터로 읽는다. `fetch("data/subway-hourly-202607.json")`을 어댑터 호출로 바꾼다.
- [ ] `tests/data.test.mjs`를 9월 기준으로 바꾼다. 지금의 "역 5곳이 모두 1호선", "서울역 08시 하차 > 승차"는 9월 데이터에서 다시 계산한 사실로 대체한다. `tests/stats.test.mjs`처럼 7월 JSON을 쓰는 단위 테스트는 그대로 둬도 된다.

확인
- `npm run check`(인자 없이)가 `역 621곳, 문제 0건`을 출력한다. 23시 값이 빠지면 여기서 걸린다.
- `node scripts/check-data.mjs data/subway-hourly-202607.json`도 계속 `역 5곳, 문제 0건`이다.
- 브라우저에서 앱을 열면 역 요약 카드와 표에 9월 역들이 나오고, 기준 달이 `2026년 9월`로 보인다.
- `grep -n "202607" index.html`에 아무것도 나오지 않는다.
- 어댑터 테스트가 있고 통과한다.
  - 변환된 행이 `count`로 읽힌다. 가산디지털단지(7호선) 11시 `total`이 `61,201`, 08시가 `403,279`, 04시가 `735`다.
  - 9월 행 수 621, 역명 528개, 여러 행인 역명 78곳.
- 좌표 매핑 테스트: 9월 승하차 데이터의 역명 528개가 모두 좌표를 찾는다(못 찾은 역 0곳).
- 9월 데이터 전체로 낮 창 답을 구했을 때 04·01시대가 답인 행이 없다. 창 안이 전부 0인 행은 `경의선 계양` 1곳뿐이다(`[]`).

## 3단계. 역 검색과 답 카드

`index.html`에 역 검색, 시간 창 선택, 답 카드를 추가한다.

할 일
- [ ] 역 검색: 역명 일부로 찾는다. 괄호 부역명을 무시한다("잠실" → `잠실(송파구청)`). 같은 역명의 노선은 한 항목으로 묶고, 노선을 고를 수도 있게 한다.
- [ ] 시간 창 선택: 프리셋 4개 + 직접 고르기. 기본값은 낮.
- [ ] 역 요약 카드의 "가장 한가한 때" 줄을 답 카드로 대체한다.
- [ ] 답 카드: 역·노선, 창 이름, 답 시간대, 하루 평균 인원, 피크 대비 비율, 데이터 기준 달, 한계 문구(평일·주말 혼합, 환승객 제외, 열차 안 혼잡도 아님).
- [ ] 창 안이 전부 0이면 "이 시간대에는 승하차 기록이 없습니다"를 보여 준다.
- [ ] 출처 표시를 두 데이터 모두에 대해 유지한다.

확인
- `python3 -m http.server 8000` 후 http://127.0.0.1:8000 에서:
  - "가산"을 입력해 가산디지털단지를 고르고 낮 창이면 답 카드가 `11시대`, 하루 평균 `2,040명`, `가장 붐비는 08시대(13,443명)의 15%`를 보여 준다.
  - 강남(2호선)은 `11시대`·`5,710명`·`36%`, 서울역(1호선)은 `14시대`·`7,531명`·`48%`다.
  - "잠실"로 `잠실(송파구청)`이 검색된다.
  - 저녁 창 직접 고르기에서 22–01시대처럼 자정을 넘겨도 답이 나온다.
  - 경의선 계양 + 낮 창에서 기록 없음 문구가 나온다.
- 역 선택부터 답 카드까지 클릭 두 번 이하(역 선택, 창 선택).
- 화면의 모든 숫자에 천 단위 쉼표가 있다(`toLocaleString("ko-KR")`).
- 새로 만든 버튼 모두와 기존 `▶ 재생` 버튼에 `aria-label`이 있고, 재생 ↔ 멈춤일 때 함께 바뀐다(`.claude/rules/html.md`).
- 개발자 도구에서 폭 375px로 놓고 검색 입력, 창 선택, 답 카드, 3D 장면, 슬라이더와 재생 버튼, 차트 카드, 표가 잘리거나 겹치지 않고 가로 스크롤이 없다.
- 콘솔에 오류가 없다.

## 4단계. 2D 차트와 3D 장면 연동

답을 2D 차트와 3D 장면에서도 보여 준다.

할 일
- [ ] 2D 차트: 고른 역의 차트에 시간 창을 띠로 칠하고 답 시간대에 표시한다.
- [ ] 3D: 승하차 데이터가 있는 역을 모두 세운다. 좌표는 2단계의 역사마스터 매핑을 쓰고 `STATION_COORDS`는 없앤다.
- [ ] 3D 축척을 새로 정한다. 범위가 남북 약 147km, 동서 약 113km라서 지금 장면(`UNIT_M` = 100m, 60×60칸 격자 = 6km)에는 들어가지 않는다. `UNIT_M`, 격자 크기, 카메라 거리와 `maxDistance`, 기둥 굵기를 함께 맞추고, 기본 시점(도심 또는 전체)을 정해 이 파일에 적는다.
- [ ] 라벨: 역이 많아 모든 라벨을 띄우면 겹친다. 고른 역과 그 주변만 라벨을 보여 준다.
- [ ] 노선 선: 지금은 "데이터 순서가 곧 노선 순서"로 선을 긋는데, 9월 CSV에서는 이 가정이 맞지 않는다. 노선 선을 빼거나 순서를 따로 정한다.
- [ ] 답이 나오면 슬라이더가 답 시간대로 이동하고, 고른 역 기둥만 또렷하게, 나머지는 흐리게 한다.
- [ ] 2D 차트와 3D 기둥은 계속 같은 `yMax`를 쓴다.

확인
- 콘솔에 "좌표가 없어 3D에서 뺀 역" 경고가 하나도 없다.
- 장면에 세운 역 수가 승하차 데이터의 역 수와 같다(환승역을 합산하면 528곳, 노선별이면 621곳 중 정한 방식 기준). 개수를 콘솔에 한 번 찍어 확인한다.
- 기본 시점에서 서울역·시청 근처 기둥이 서로 구분되고, 휠로 줄이면 수도권 전체가 들어온다.
- 가산디지털단지 + 낮 창을 고르면 슬라이더 표시가 `11시대`로 바뀌고, 그 역 기둥이 강조된다.
- 3D 장면에서 기둥에 마우스를 올린 값과 2D 차트 툴팁의 같은 시간대 값이 같다.
- 개발자 도구 Performance 패널에서 슬라이더 재생 중 프레임이 눈에 띄게 끊기지 않는다(대략 30fps 이상). 기둥이 1,000개가 넘으므로 필요하면 `InstancedMesh`로 바꾼다.
- `prefers-reduced-motion`을 켜면 기둥이 애니메이션 없이 바로 바뀐다.
- 375px 폭 확인(3단계와 같은 항목)을 다시 한다.
