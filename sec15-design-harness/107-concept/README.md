# 디자인 하네스란 — 오늘 끝나면 이런 결과 (개념 · 무료 미리보기)

완성 결과(따릉이 대여소 지도 앱, 피그마 화면 8장)를 먼저 보고, 하네스 = 규칙 파일 + 검사 + 사람 승인, 여덟 단계(PRD → 리서치 → 정보 구조 → 와이어프레임 → 디자인 시스템 → 피그마 → 검증 → 핸드오프)와 사람 승인 3곳, 디자인 기법 8가지(토큰 · 타입 스케일 · 4/8 그리드 · 명도 대비 · 터치 영역 · 상태 · 컴포넌트 · 마이크로카피)가 검사로 바뀌는 원리를 그림으로 봅니다.

숫자의 무게를 구분합니다: 명도 대비 4.5:1·3:1 = 표준([WCAG 2.2 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)), 44pt = 플랫폼 가이드([Apple HIG](https://developer.apple.com/design/human-interface-guidelines/buttons)), 4의 배수 그리드 = 실무 관행, 글자 크기 5단계 이하 · 정렬선 4개 이하 = 경험칙(바꿔도 됨).

같은 부탁을 하네스 없이/있이 한 실험: 색 13→7, 글자 크기 13→4, 대비 미달 24→0 / 대신 시간 약 5.8배 · 비용 약 5.6배, 블라인드 비평 11 vs 12점(→ `117-ab-compare`).
대상: 피그마를 쓰는 디자이너 · 기획자. 코딩 경험 없어도 됩니다.
