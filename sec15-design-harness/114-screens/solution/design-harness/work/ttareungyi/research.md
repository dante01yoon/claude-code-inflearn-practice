# Research: 따릉이 대여소 현황

## 핵심 과업
휴대폰(390x844)에서 가까운 대여소에 자전거가 남아 있는지 목록과 상세로 빠르게 확인하고, 데이터가 없거나 실패한 경우 다시 시도하게 한다.

## 관찰한 패턴
- 모바일 상단은 로고, 둥근 버튼 하나, 햄버거 메뉴로 단순하다 (ref-citibike, ref-baywheels, ref-capitalbikeshare, ref-divvy, ref-bluebikes 공통).
- 화면당 주요 행동 버튼은 하나다 (ref-baywheels, ref-capitalbikeshare, ref-divvy). 우리 화면도 목록은 행 탭, 상태 화면은 "다시 시도" 하나로 둔다.
- 브랜드 색 한 가지를 헤더 버튼과 히어로에 일관되게 쓴다 (ref-capitalbikeshare, ref-divvy). 0대 경고색은 브랜드색과 구분한다.
- 데이터 공개 페이지는 이용 정책/라이선스 링크를 본문에 둔다 (ref-citibike, ref-bluebikes). 우리는 하단 출처표시로 옮긴다.
- 데이터 필드는 대여소 이름, ID, 위도, 경도로 구성된다 (ref-citibike, ref-bluebikes). 우리 상세 화면의 항목과 같다.
- 제공자 로고를 세로선으로 병기한다 (ref-divvy).

## 수집 한계
- 따릉이 공식 사이트(ref-bikeseoul)는 웹 방화벽 차단, Santander Cycles(ref-santander)는 보안 확인 화면으로 차단. 우회하지 않았고 blocked 처리했다.
- Vélib' 지도도 오류 화면이라 제외했고, App Store 따릉이 링크는 404라 제외했다.
- 쓸 수 있는 5개는 모두 마케팅/데이터 안내 페이지다. 대여소 목록, 상세, 빈/에러 상태를 보여 주는 실제 앱 화면은 수집하지 못했다. 이 세 가지의 레이아웃 근거는 약하므로 와이어프레임 단계에서 사람이 따릉이 앱 화면 캡처를 주면 보강한다.
- 해외 서비스 위주이며 한국어 UI 레퍼런스는 없다.

## 데이터에서 본 것
`data/stations.json` (서울 열린데이터광장 OA-15493, 공공누리 제1유형, 대여소 5곳):
- 자전거 수는 0, 1, 4, 5, 6대로 0대가 ST-5(103. 망원역 2번출구 앞) 한 곳. 0대 강조 표시를 확인할 사례가 있다.
- 거치대 수는 5~15. 남은 자전거 1대/15 같은 값도 있어 "남은 수 / 거치대 수" 형식이 자연스럽다.
- `shared` 필드(0~80)는 PRD가 쓰지 않으므로 화면에 올리지 않는다. 의미를 확인하지 못했다.
- 이름 앞에 번호("102.")가 붙어 있다. 표시 때 그대로 둘지 PRD 결정이 필요하다.
- 화면 구성 제안: 목록, 상세, 빈 상태, 에러 상태의 4개(사용자 요청 3~4개 범위).
