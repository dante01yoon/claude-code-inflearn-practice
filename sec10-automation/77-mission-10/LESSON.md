# 섹션 10 · 77강 미션 10 — 아침 리포트에 '가기 좋은 시각' 더하기

## 미션
아침 리포트가 `claude -p`에 넘기는 요약 JSON 스키마에 **광화문·덕수궁 가기 좋은 시각** 칸을 더하세요. 클로드가 12시간 예측을 보고 고르게 하고(예측에 없는 시각은 지어내지 않기), 리포트 화면에 보이게, 테스트 통과 후 커밋.
도전: 이 변경을 PR로 올려 74강의 자동 리뷰를 받기. 매일 아침 돌리려면 75강 루틴에 맡기기.

## 채점표
1. 스키마에 새 칸 2. 실제 실행 결과 JSON에 값 3. 화면에 표시 4. 예측에 있는 시각만 5. 테스트 통과·커밋 6. (도전) PR 자동 리뷰

## 정답 풀이 (입력한 것 그대로)
짧게 먼저:
```text
리포트에 오늘 광화문·덕수궁에 가기 좋은 시각도 넣어 줘. claude -p가 12시간 예측을 보고 고르게 하고, 화면에도 보여 줘
한 번 돌려 보고 커밋해 줘
```
→ 2분 1초. `visit`(지금 값 + 오늘 안의 예측)을 넘기고 요약 스키마에 `visit` 추가, 화면에 시각별 칸 + 추천 표시, 테스트 132개 통과, 커밋 a130b69. 그런데 고른 시각이 **06:00·07:00·08:00**(새벽, 숫자로만 가장 한가함) → 빗나감.

자세하게 다시(`claude --continue`):
```text
추천 시각은 실제로 놀러 갈 만한 낮 시간(10시~18시) 안에서만 골라 줘. 그 시간대 예측이 아직 없으면 고르지 말고 '아직 예측 없음'이라고 쓰고, 고른 까닭에는 예측 혼잡도와 추정 인구를 그대로 적어. 고친 다음 한 번 돌려 보고 커밋해 줘
```
→ 1분 25초. 후보(`candidates`, 10:00~18:00)만 넘기고, 후보 밖 추천은 저장 전에 `checkVisitBest`가 걸러 냄, 낮 시간 밖 칸은 흐리게, 테스트 133개 통과, 커밋 4f8bfa4. 결과(06:00 KST 기준, sample 키): 10:00·18:00(보통 28,000~30,000명), 11:00(보통 30,000~32,000명), 피할 시각 13:00~15:00(약간 붐빔 34,000~36,000명).

결과 화면: `npm run report` → `npm start` → http://127.0.0.1:8000/reports/
