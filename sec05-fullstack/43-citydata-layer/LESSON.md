# 섹션 5 · 43강 같은 지도에 121곳 레이어 추가

## 개념
- 서울 실시간 도시데이터(OA-21285): 121곳의 추정 인구 범위·혼잡도 4단계(여유·보통·약간 붐빔·붐빔)·12시간 예측. 한 번에 1곳 → 121번 호출.
- 공개 `sample` 키는 어느 장소를 물어도 광화문·덕수궁 1곳만 돌려준다(2026-10-12 실측). 일반 인증키를 `.env`의 `SEOUL_OPENAPI_KEY`에 넣으면 같은 코드로 121곳(2026-10-13 실측: 121곳 모두 받음, 오류 0, 약 4.5초).
- 호출량: 한 번에 1곳이라 121번. 공식 페이지에 이 API의 하루 호출 한도는 적혀 있지 않음(하루 1,000번 한도는 실시간 지하철 인증키 안내). 서버가 5분 저장하므로 화면을 몇 번 열어도 5분에 121번만 묻는다.
- 장소는 면 → 영역 파일(`서울시 주요 121장소 영역.zip`, SHP, WGS84)을 다각형으로 읽어 인구만큼 밀어 올림(deck.gl).
- 브라우저 → 우리 서버 `/api/citydata` → 121곳을 8개씩, 5분 캐시 → 키는 서버 밖으로 나가지 않음.

## 준비
열린데이터광장 OA-21285 페이지의 파일 두 개(`서울시 주요 121장소 영역.zip`, `서울시 주요 121장소 목록.xlsx`)를 `data/raw/citydata/`에 넣음.

## 내 인증키 넣기 (직접)
```text
# .env (저장소에 올리지 않음 · .gitignore에 있음)
SEOUL_OPENAPI_KEY=<열린데이터광장에서 받은 일반 인증키>
```
키는 서버(`server.mjs`, `api/citydata.js`)만 읽고 브라우저로 가는 응답과 오류 문구에는 넣지 않는다(`scrub`). 발급은 30강 「인증키 신청 → 일반 인증키」.

## 입력한 것 (그대로)
```text
실시간 도시데이터 121곳을 지하철 지도에 새 레이어로 얹어 줘. 인구만큼 3D로 솟게, 혼잡도는 색으로, 12시간 예측 슬라이더도. 영역 파일은 data/raw/citydata에 있어
커밋해 줘
```
→ 약 7분 50초. `citydata-areas.mjs`(의존성 없이 zip·shp·dbf 해석), `realtime-citydata.mjs`·`api/citydata.js`·`server.mjs`(`/api/citydata`), `subway.html`(레이어·범례·예측 슬라이더·숨기기), 테스트 46개 통과. 녹화 때는 sample 키라 121곳 화면은 서버 응답을 가짜 값으로 바꿔 확인했다고 보고 → 그 뒤 내 일반 인증키로 직접 확인(아래). 혼잡도 색은 공식 색이 아니라 직접 정한 색. 커밋 `7bc3d29`.
