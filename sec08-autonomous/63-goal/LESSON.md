# 섹션 8 · 63강 `/goal` — 완료 조건을 줄 때까지 여러 턴 계속

## 개념: 완료 조건을 적은 작업 지시서
- `/goal <조건>`을 넣으면 조건 자체가 첫 지시가 되어 클로드가 바로 일을 시작합니다. 한 턴이 끝날 때마다 **작고 빠른 모델(판정 모델)**이 조건과 지금까지의 대화를 읽고 *아직 · 달성 · 불가능* 중 하나로 판정합니다. 아직이면 그 이유를 들고 다음 턴을 이어 가고, 달성하면 목표가 지워집니다.
- 일하는 사람(클로드)과 끝났는지 판단하는 사람(판정 모델)이 다르다는 것이 핵심. 판정 모델은 명령을 실행하거나 파일을 읽지 않고 **대화에 드러난 것만** 봅니다 → 확인 결과가 대화에 보이게 조건을 씁니다.
- 판정은 세션 범위의 프롬프트 기반 Stop hook으로 돌아갑니다(녹화에서 `running Stop hook` 줄로 보임). 권한 모드는 바꾸지 않으므로 자리를 비울 때는 auto 모드와 함께 씁니다.

| 명령 | 하는 일 |
|---|---|
| `/goal <조건>` | 시작(조건 최대 4,000자, 이미 있으면 바꿔 끼움) |
| `/goal` | 상태 — 조건 · 걸린 시간 · 턴 수 · 토큰 · 최근 판정 이유 |
| `/goal clear` | 지우기(`stop`·`off`·`reset`·`none`·`cancel`도 같음, `/clear`도 지움) |

## 조건 잘 쓰는 법 (공식 문서)
측정할 수 있는 **끝 상태** 하나 · 그걸 증명하는 **확인 방법** · 가는 길에 바꾸면 안 되는 **지킬 것** · 필요하면 **턴/시간 제한**(예: "10턴 안에 못 하면 멈춘다").

## 실습 1 — 짧은 조건 (입력한 것 그대로)
```text
/goal subway.html에 두 역 비교 그래프 추가. npm test 다 통과하면 끝
```
- 결과: `station-compare.mjs`(compareDaily) + 테스트 4개 + subway.html 「두 역 비교」 패널. `✔ Goal achieved (3m · 1 turn · 18.4k tokens)`.
- 도중에 You should know 노트: "목표 조건이 'npm test 통과'라서, 비교 그래프가 화면에서 실제로 잘 그려지는지는 확인하지 않고 끝날 수 있습니다." (62강에서 본 노트는 "A역은 고른 노선만, B역은 늘 모든 노선 합계" — 이번 구현 요약에도 "위에서 고른 역은 노선 칩을 따르고, 비교할 역은 노선을 합친 값"으로 그대로 남음.)
- 빗나간 점: ① 두 역의 기준이 다름 ② 화면 확인이 조건에 없음(이번엔 클로드가 스스로 헤드리스 Chrome으로 확인했지만 조건이 요구한 것은 아님).

## 실습 2 — 자세한 조건 (프롬프트를 좀 더 자세히)
```text
/goal 두 역 비교 그래프를 같은 기준으로 맞춘다. 끝난 상태: 두 역 모두 전체 노선 합계 하루 평균으로 그리고, 범례에 '전체 노선 합계'라고 적혀 있다. 확인: npm test 통과, 헤드리스 브라우저로 강남과 홍대입구 비교 화면을 찍어 두 선과 범례가 보이는지 본다. 지킬 것: 기존 테스트 파일은 고치지 않는다. 10턴 안에 못 하면 멈춘다.
커밋해 줘
```
- 결과: `✔ Goal achieved (1m · 1 turn · 6.3k tokens)`. 헤드리스로 강남·홍대입구 비교: 하루 합계 강남 148,091명 · 홍대입구 184,407명, 두 역 모두 18시대 피크, 차이가 가장 큰 때 16시대(4,428명). 피크 이름표가 겹치는 것은 원래 있던 배치 문제라 고치지 않고 알려 줌. 커밋 `485e6c7`(비교 기능 + 이번 수정).

## 결과 화면
`npm start` → http://127.0.0.1:8000/subway.html → 역 찾기에 `강남` → 아래 「두 역 비교」 칸에 `홍대입구` → 범례 "강남 · 전체 노선 합계 / 홍대입구 · 전체 노선 합계", 꺾은선 2개, 요약(하루 합계·피크·차이가 가장 큰 시간대).
