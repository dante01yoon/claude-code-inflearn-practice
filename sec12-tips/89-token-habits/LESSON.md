# 섹션 12 · 89강 토큰 아끼는 습관 정리 📏 — /clear · 모델 고정 · 큰 출력 거르기

## 이번 수업에서 할 것
- 클로드 코드는 부탁마다 대화 전체를 다시 보낸다(78강). 그래서 쌓인 것을 줄이는 게 토큰을 아끼는 길이다.
- 습관 세 가지를 공식 문서로 확인하고, 그중 두 가지(`/clear`, 큰 출력 거르기)를 `/context`의 Messages 줄로 직접 잰다.

촬영: VS Code 내장 터미널(code-server), Claude Code v2.1.299, 오토 모드, Opus 5.5, 2026-10-17. 앱 브랜치 `sec12-tips`. 세션 중 `/model`은 쓰지 않음.

## 공식 문서로 확인한 것
| 내용 | 근거 |
|---|---|
| 관련 없는 작업으로 바꿀 때 `/clear`로 새로 시작 — 오래된 컨텍스트는 이후 모든 메시지에서 토큰을 낭비 | [비용 관리 · 토큰 사용량 줄이기](https://code.claude.com/docs/ko/costs) |
| 훅으로 테스트 출력을 걸러 실패만 보이게 하면 수만 토큰을 수백으로 줄일 수 있음 | 같은 페이지 |
| 세션 시작 때 모델·effort를 고르고 작업 중 바꾸지 않기. 모델을 바꾸면 내용이 같아도 다음 요청이 캐시 없이 전체 대화를 읽음 | [프롬프트 캐싱](https://code.claude.com/docs/ko/prompt-caching) |

## 입력한 것 (그대로)
```text
claude
/context
subway.html에서 시간 슬라이더가 어떻게 움직이는지 짧게 설명해 줘
/context
따릉이 테스트는 몇 개야? 숫자만
/context
/clear
따릉이 테스트는 몇 개야? 숫자만
/context
/exit
claude
npm test 돌리고 출력은 전부 그대로 읽어 줘. 다른 명령은 돌리지 마
/context
/clear
npm test 2>&1 | tail -4 로 돌려서 결과만 한 줄로 알려 줘. 다른 명령은 돌리지 마
/context
/exit
```

## 📏 /context Messages 실측 (이번 녹화 1회)
| 상황 | Messages | 메모 |
|---|---|---|
| 시작 직후 | 10 | 부탁 전 |
| 시간 슬라이더 설명 뒤 | 23.4k | 큰 파일을 읽은 결과가 대화에 쌓임 |
| 다른 질문 · `/clear` 없이 | 27.1k | 앞 작업까지 함께 실림 (답: 10개) |
| 같은 질문 · `/clear` 뒤 | 9.8k | −17.3k |
| `npm test` 출력 전부 읽기 | 19.3k | 테스트 148개 줄이 대화에 |
| `npm test 2>&1 \| tail -4` | 9.8k | −9.5k · 결과는 같음(실패 0) |

짧은 질문 하나에도 이 폴더에서는 약 9.8k에서 시작했다. 숫자는 폴더·질문에 따라 달라지므로 각자 `/context`로 재 볼 것.

참고: 2.1.299에서 `!npm test`(셸 직접 실행)는 결과를 받은 클로드가 이어서 답하는 동작이 섞여 측정이 흐려져서, 두 번째 실험은 평소 말로 부탁하는 방식으로 다시 녹화했다.
